# Docklands Creative – Responsive Design

## 1. Purpose

This document records the responsive design approach used for the Docklands
Creative website redesign.

The objective is to ensure that the website maintains its visual hierarchy,
usability and conversion pathways across desktop, tablet and mobile devices.

---

## 2. Responsive Philosophy

The design follows a responsive-first implementation approach.

Content should adapt to the available screen width rather than simply
shrinking the desktop layout.

The main priorities are:

- Readability
- Navigation accessibility
- Clear hierarchy
- Touch-friendly interaction
- Consistent spacing
- Responsive imagery
- CTA visibility
- Fast and intuitive mobile navigation

---

## 3. Desktop Layout

The desktop design provides the full visual experience.

Key characteristics include:

- Full navigation menu
- Large hero composition
- Two-column hero layout
- Multi-column service cards
- Four project cards
- Horizontal process layout
- Large section headings
- Expanded footer navigation

The desktop layout provides sufficient space for visual storytelling while
maintaining a structured content hierarchy.

---

## 4. Tablet Layout

The tablet experience acts as an intermediate layout.

The design should:

- Reduce horizontal spacing
- Reduce the number of columns where necessary
- Maintain readable typography
- Preserve CTA visibility
- Allow cards to wrap naturally
- Maintain the visual hierarchy of major sections

Two-column layouts may become single-column layouts where screen width
requires it.

---

## 5. Mobile Navigation

The desktop navigation is replaced by a compact mobile navigation.

The mobile experience prioritises:

- Simple navigation access
- Clear menu interaction
- Visible primary CTA
- Minimal visual clutter

The navigation should remain accessible without occupying excessive screen
space.

---

## 6. Mobile Hero

The desktop hero uses a text-and-visual composition.

On mobile, the content is stacked vertically:

1. Hero label
2. Main heading
3. Supporting text
4. Primary CTA
5. Secondary CTA
6. Supporting visual

This ensures the core message remains visible before secondary content.

---

## 7. Mobile Services

The four service cards transition from a multi-column layout into a
single-column or stacked arrangement.

Each service maintains:

- Service title
- Short description
- Supporting icon/visual
- Clear hierarchy

The objective is to allow users to scan services comfortably without
horizontal compression.

---

## 8. Mobile Projects

The project portfolio changes from a desktop grid into a vertically stacked
presentation.

Project imagery remains visually prominent.

Each project maintains:

- Project name
- Category/service
- Short description
- Visual preview
- Link/action

The project section should remain one of the strongest visual areas of the
mobile experience.

---

## 9. Mobile Value Proposition

The four value propositions stack vertically.

The structure becomes:

1. Results Driven
2. Creative Excellence
3. Clear Communication
4. Long-Term Partners

Spacing is increased between individual items to improve readability.

---

## 10. Mobile Process

The five-step process changes from a horizontal arrangement into a vertical
sequence:

01 — Discover

02 — Plan

03 — Design

04 — Develop

05 — Launch

This makes the process easier to follow on narrow screens.

---

## 11. Mobile Testimonial

The testimonial remains a full-width high-impact section.

The typography is reduced appropriately while preserving the emphasis of the
testimonial message.

The client attribution remains visually separated from the main quotation.

---

## 12. Mobile Insights

The three insight cards are stacked vertically.

Each card maintains:

- Image
- Category
- Article title
- Supporting information
- Reading/action link

The section should remain easy to scan without excessive text.

---

## 13. Mobile CTA

The final CTA remains prominent.

The primary consultation action should be large enough to be comfortably
used with a finger.

The CTA section should maintain strong contrast and sufficient spacing.

---

## 14. Responsive Typography

Typography scales between screen sizes.

### Desktop

Large display typography is used for:

- Hero heading
- Major section headings

### Tablet

Heading sizes are reduced while maintaining hierarchy.

### Mobile

Typography becomes more compact while maintaining:

- Clear H1
- Distinct H2 sections
- Readable body text
- Comfortable line height

Text should never become so small that readability is compromised.

---

## 15. Responsive Spacing

Spacing scales according to screen size.

Desktop uses larger:

- Section padding
- Content gaps
- Card spacing
- Hero spacing

Mobile uses tighter spacing while preserving enough breathing room between
content groups.

---

## 16. Images and Visuals

Images should scale proportionally and avoid distortion.

Project images should maintain consistent aspect ratios where possible.

Decorative visuals should not interfere with:

- Navigation
- Text
- Buttons
- Accessibility
- Content readability

---

## 17. Touch Interaction

Interactive elements should be designed for touch.

Buttons and links should have sufficient:

- Size
- Spacing
- Contrast
- Visual feedback

Interactive elements should not be positioned so closely together that users
could accidentally select the wrong action.

---

## 18. Responsive Testing

The implemented website will be tested at:

- Desktop
- Laptop
- Tablet
- Mobile

Testing will focus on:

- Navigation
- Typography
- Images
- Cards
- Buttons
- Forms
- Section spacing
- Horizontal overflow
- CTA visibility
- Overall visual consistency

---

## 19. Figma-to-WordPress Relationship

The responsive Figma designs will act as the reference for the WordPress
implementation.

During development, the website will be compared against the Figma design
at equivalent screen sizes.

Where implementation differences occur, priority will be given to:

1. Usability
2. Accessibility
3. Responsive behaviour
4. Visual consistency
5. Figma fidelity

---

## 20. Responsive Design Outcome

The final responsive experience should allow users to move through the same
core journey regardless of device:

Discover → Understand → Explore → Trust → Enquire

The content structure remains consistent while the layout adapts to the
available screen space.
